1. **一句话本质**：逼自己压缩到一句
2. **讲给门外汉**：比喻 + 白话，禁止堆术语
3. **把比喻拆开**：对照真实机制，补上刚才藏起来的细节
4. **放到训练/推理机器上**：这根线在集群里到底扛什么活
5. **常见假懂**：最容易说对但想错的点
6. **费曼自测**：合上笔记口述；卡壳就回到对应段，不要往下一节逃

约定：一次只学一节。学完、自测过关，再根据对话把下一节写进来。全部内容只放这一份文档，按学习顺序追加小节。

## 1. PCIe

### 1.1 一句话本质

PCIe 是 CPU 跟外设（GPU、网卡、NVMe）之间的**点对点、分包、串行高速公路**。卡插在主板上，绝大多数时候，它就是那张卡和「主机世界」之间唯一的正门。

### 1.2 讲给门外汉

想象一座城市：

- **市政厅**是 CPU（更精确一点：CPU 里的 Root Complex，树根）。
- **各栋楼**是 GPU、网卡、SSD。
- **PCIe 不是一个大家共享的大广场**（那是很老的 PCI：所有设备挂在同一条总线上，同时只能有一个人说话）。
- 它是**市政厅通往每栋楼的专属马路**。你和邻居之间默认没有门，要串门得先绕回市政厅。

马路有多宽、限速多少，决定了一次能拉多少货：

- **宽度 = lane 数**。常见是 x1、x4、x8、x16。一块训练卡通常占满 x16，就像独占一条 16 车道的路。
- **限速 = 代数（Gen）**。Gen3 → Gen4 → Gen5，大约每代翻倍。同一条 x16，Gen4 大约单向 32 GB/s，Gen5 大约 64 GB/s。
- 路是**双向的**：去和回各有一组线，可以同时跑。但「同时跑满」只发生在你真的两边都有流量时；只做 Host→GPU 拷贝，回程那半就空着。

车上装的不是整辆卡车直接开进去，而是**切成小包裹（Transaction Layer Packet, TLP）**。每个包裹写着：去哪、读还是写、多少字节。沿途有人核对有没有损坏、丢了就重传。这就是为什么 PCIe 看起来像「一根线」，协议上却很像迷你网络。

还有一件反直觉的事：**GPU 虽然靠 PCIe 插在机器上，但 GPU 自己的显存（HBM）比这根线快一到两个数量级**。H100 的 HBM 大约 3 TB/s，PCIe Gen5 x16 大约 64 GB/s，差了约 50 倍。所以：

> 卡里算得再快，一旦数据要进出这张卡、还得走 PCIe，瞬间就堵在正门口。

后面要学的 NVLink、HCCS、RDMA、GPUDirect，全是在回答同一个问题：**能不能少走、或者干脆不走这扇正门。**

### 1.3 把比喻拆开

#### 拓扑是树，不是广场

PCIe 的标准拓扑是一棵树：

```text
            CPU / Root Complex
                    │
         ┌──────────┼──────────┐
      Switch      GPU0        NIC
         │
    ┌────┴────┐
   GPU1      GPU2
```

- **Root Complex**：树根，通常在 CPU 里。所有配置空间、地址翻译，从这里长出来。
- **Endpoint**：叶子，GPU、网卡、NVMe 都是。
- **Switch**：分叉点。高端主板 / 多卡服务器里很常见：CPU 的 PCIe lane 不够分给 8 张卡，就先接到交换机再分下去。

默认语义是：**两张卡要说话，包会沿着树往上走到最近的共同祖先，再下去**。如果共同祖先是 CPU，数据就「绕路经过主机」。这就是为什么「同一台机器里的 GPU 和网卡」并不自动等于「它们能直接握手」。

有一个重要例外：**Peer-to-Peer（P2P）**。若 Root Complex / Switch 允许，GPU 和网卡可以不经过系统内存直接传。NVIDIA 的 GPUDirect RDMA、GPUDirect P2P 就建立在这个能力上。它不是 PCIe 默认就有、也不是软件喊一声就通：中间路径上任何一跳禁止 P2P（常见是 ACS、IOMMU 策略、经过 CPU 内部的跨 socket 路径），包就会被强制绕回主机内存，延迟和带宽一起掉下来。

#### 一次传输长什么样

把一次「CPU 把模型权重写进 GPU」拆开：

1. 软件拿到这张卡在 PCIe 配置空间里声明的 **BAR（Base Address Register）**。BAR 的意思是：请把我设备上的某段寄存器 / 某段显存，映射进 CPU 能看见的物理地址。
2. CPU 对这个地址做 load/store，或者更常见地，让 DMA 引擎去搬（下一节专门讲）。对 PCIe 来说，这些都变成 **TLP**。
3. TLP 常见类型只要先记住三个：
   - **Memory Write**：把数据推过去，通常 posted（发完不等完成包）。
   - **Memory Read**：去对面拿数据，必须等 **Completion** 带着数据回来。所以「读」往往比「写」更吃延迟。
   - **Config**：枚举设备、读 VID/DID、配 BAR，开机和热插拔时用。
4. 下面还有 Data Link 层做序号、ACK/NAK、CRC；再下面 Physical 层是差分串行 lane。学到「它是分包的可靠链路」就够，不必把 LTSSM 状态机背下来。

CPU 自己一字节一字节抠设备，叫 **Programmed I/O（PIO）**，只适合写门铃、敲门铃、改几个寄存器。大块张量拷贝绝不能这么干，那是 DMA 的工作。PCIe 提供的是路，DMA 才是会自己开车的搬运工——所以下一节是 DMA。

#### 带宽怎么心算

不必背表，用三个数就能估：

- 每条 lane 的裸速率：Gen3 = 8 GT/s，Gen4 = 16，Gen5 = 32，Gen6 = 64。GT/s 可以先粗暴当成「每秒传输多少个码元」。
- 编码开销：Gen1/2 用 8b/10b（20% 浪费）；Gen3–5 用 128b/130b（大约 1.5%）；心算时 Gen3 及以上可以近似「GT/s × lane 数 / 8 = GB/s」。
- 再乘 lane 数。

所以：

| 链路 | 心算单向 | 典型出现位置 |
|------|----------|--------------|
| Gen3 x16 | ~16 GB/s | 较老的服务器、消费级 |
| Gen4 x16 | ~32 GB/s | A100 PCIe、很多 2020 前后训练机 |
| Gen5 x16 | ~64 GB/s | H100/H200 PCIe、新一代网卡 |
| Gen5 x16 双向 | ~128 GB/s | 仅当读写同时打满 |

注意三个坑：

1. 这是**链路理论值**，再扣 TLP 头、对齐、PCIe 交换机、NUMA 跨 socket，应用层常见只能吃到六到八成。
2. `nvidia-smi` 里看到的 PCIe 代数，是**当前协商出来的**，不是卡的上限。插在 Gen4 槽上的 Gen5 卡，就按 Gen4 跑。
3. 一张卡「支持 Gen5」和「这台机器到这张卡的整条路径都是 Gen5」是两件事。CPU 口、转接板、Switch、线缆，任何一段是 Gen4，整条链路就降到 Gen4。

#### 插槽、NUMA、亲和性

双路服务器里这张树其实有两棵，每棵长在一颗 CPU 上：

```text
 CPU0 ── PCIe ── GPU0, GPU1, NIC0
 CPU1 ── PCIe ── GPU2, GPU3, NIC1
      └── QPI/UPI（两颗 CPU 之间）
```

进程绑在 CPU0，却去拷 GPU3 的显存，数据要先跨 UPI 再到 CPU1 的 PCIe 树。这就是 **PCIe / NUMA 亲和性**。集群排障时「带宽只有理论值一半」，第一反应经常是：是不是跨 NUMA 了。

`nvidia-smi topo -m`、`lspci -tv`、`numactl --hardware` 就是在读这张树。看见 `PIX` / `PXB` / `NODE` / `SYS` 这些标记，含义是两张 GPU 的最近公共祖先分别是：同一个 PCIe 桥、同一个 PCIe 交换机但跨桥、同一 NUMA 节点、跨 CPU。越往上走，P2P 越慢、越可能根本不通。

### 1.4 放到训练/推理机器上

只记四条，已经够把后面的 NVLink / RDMA 接上：

1. **Host ↔ GPU 的 `cudaMemcpy`、模型加载、tokenizer 后的 batch 上传，默认走 PCIe。** 这就是「卡很闲、但输入在排队」时最常见的物理原因。
2. **没有 NVLink / HCCS 的多卡机器，GPU–GPU 也走 PCIe**（NCCL 会选 `P2P` 或经过主机）。8 卡消费级盒子打 AllReduce，经常就是在打 PCIe 的上限。
3. **网卡也是 PCIe 设备。** 即便网上是 400 GbE / IB，NIC 到 GPU 这一跳仍然可能卡在 PCIe。所以有 GPUDirect：让 NIC 直接 DMA 进显存，少一次「NIC → 主机内存 → GPU」的折返。
4. **HBM ≫ NVLink ≫ PCIe ≈ 单条高档网卡。** 数量级记这个就行。优化通信，本质是把流量从慢的那一层抬到快的那一层，或者干脆别出卡。

一张很粗糙但好用的尺子（数量级，不是参数表）：

```text
HBM           ~ 几 TB/s     卡内部
NVLink/HCCS   ~ 几百 GB/s   卡和卡（节点内 / 超节点内）
PCIe Gen5 x16 ~ 64 GB/s     卡和主机、卡和网卡
400 GbE/IB    ~ 50 GB/s     节点和节点（还要再过一次 PCIe 进卡）
```

所以「节点内用 NVLink、节点间用 IB/RoCE」不是厂商口号，是带宽层级逼出来的分工。

### 1.5 常见假懂

- **「PCIe 是总线，大家轮流说话。」** 老 PCI 才是共享总线。PCIe 是点对点串行链路，一张卡一条（或几条）独立的 link。
- **「x16 一定比 x8 快一倍，所以插满就行。」** 还取决于 Gen、路径上有没有 Switch、是不是被 CPU 口拆分（bifurcation）。16 条物理 lane 被拆成两个 x8，两张卡各自只有 x8。
- **「机器里有 GPU 和网卡，RDMA 就自然进显存。」** 没有 P2P / GPUDirect，数据仍会在主机内存中转，多一次拷贝，CPU 和 PCIe 两边都更忙。
- **「PCIe 带宽是双向之和，拷权重时按 128 GB/s 算。」** 单向拷贝只能吃一个方向。H2D 打满 Gen5 x16，大约就是 64 GB/s 量级。
- **「PCIe 5.0 的卡插进去就是 5.0。」** 整条链路最弱的那一跳说了算，包括 CPU 根复合体、转接卡、Riser、线缆。
- **「NVLink 取代了 PCIe。」** 没有。NVLink 是 GPU–GPU（以及部分 CPU–GPU）的旁路高速路；卡仍然要靠 PCIe 跟主机、跟多数网卡说话， barb 系统管理、枚举、以及没有 NVLink 的那部分流量。

### 1.6 费曼自测

合上笔记，用自己的话答。答不出就只回这一节，不要开始 DMA。

1. 用「市政厅和楼」把 PCIe 讲一遍：谁是树根、谁是叶子、两栋楼默认怎么串门。
2. lane、Gen、双向，这三个词各管什么。为什么说「H100 PCIe 大约 64 GB/s」时，通常指的是单向。
3. TLP 是什么。为什么「读」往往比「写」更怕延迟。
4. BAR 解决的是哪一类问题：设备内部的地址，怎么变成 CPU 能 load/store 的地址。
5. 为什么 GPU 算力爆表，模型加载、KV 跨进程搬运却常常看起来在「等 I/O」。把 HBM、PCIe、网卡三层数量级说出来。
6. 什么是 P2P。举一个「看起来是机内通信、实际绕回了主机内存」的例子。
7. 双路服务器上，进程绑错 NUMA 会发生什么。你打算用哪条命令确认 GPU 和 NIC 是不是挂在同一棵 PCIe 树上。
8. 一句话说明：后面为什么必须学 DMA，而不能停留在「PCIe 是一根很快的线」。

### 1.7 这一节真正该留下的图

```text
主机 DRAM
    │
   CPU / Root Complex          ← 树根；跨 socket 还要再走 UPI
    │
    ├── PCIe link ── GPU       ← 正门；H2D/D2H、没有 NVLink 时的卡间
    │                 └── HBM  ← 卡内，快一到两个数量级
    │
    ├── PCIe link ── NIC       ← 网卡也是 PCIe 端点
    │
    └── PCIe Switch ── 更多 GPU / NVMe
```

能把这张图从脑子里画出来，并且指着每根线说出「它比谁慢、什么流量会走它」，PCIe 这一节就过关了。

下一节预告：路已经有了，谁来开车？CPU 自己搬叫 PIO，设备自己搬叫 **DMA**。RDMA 只是「把 DMA 的资格交给远端网卡」——所以 DMA 必须紧挨着这一节学。
