# 拿到新模型时先观察什么

开口先问四类问题：模型长什么样、跑在什么硬件和软件上、流量和 SLO 是什么、并行和 Serving 模式怎么切。问不清就不要下结论。

---

## 1. 模型

| 问 | 为什么问 |
|----|----------|
| Dense 还是 MoE？专家数、激活专家数？ | MoE 多一条 EP / 专家路由和 all-to-all |
| 参数量、层数、隐层、头数 | 决定单步计算量和通信切分 |
| 最大上下文、是否多模态 | 长上下文打带宽和 KV；多模态有独立预处理阶段 |
| 精度（BF16 / FP8 / INT8） | 算力、带宽、Kernel 实现都变 |

---

## 2. 硬件与软件栈

| 问 | 为什么问 |
|----|----------|
| 卡型、卡数、互联 | 单卡算力墙 vs 多卡通信墙 |
| 显存容量 | KV、激活、权重谁先把容量吃满 |
| 推理框架与版本 | Scheduler、Attention backend、图编译路径不同 |
| 编译器 / 运行时版本 | 融合、Layout、官方 Kernel 是否可用 |

先写下一组「能复现实验」的版本号，后面对比才有意义。

---

## 3. 负载与目标

不要用通用随机 Benchmark 代替真实画像。至少弄清：

- 并发怎么分布，到达是平稳还是尖峰
- 输入长度、输出长度分布（ISL / OSL）
- 长短请求是否混部
- SLA：P99 时延、TTFT、TPOT、还是吞吐优先

同一模型，短 prompt 高并发和长上下文低并发，瓶颈通常不在同一层。

基线至少记下：Throughput（tokens/s 或 QPS）、TTFT、TPOT、E2E、成功率、显存、NPU/GPU 利用率。

---

## 4. Serving 与并行切法

| 问 | 观察点 |
|----|--------|
| 混合还是 PD 分离 | 1 hop vs 2 hop；KV 要不要跨节点 |
| TP / PP / DP / EP 怎么组合 | 通信集合、切分粒度、专家负载是否均匀 |
| Continuous batching 开了没 | Decode 能否把气泡填上 |
| Prefix / KV cache 策略 | 多轮、系统 prompt 是否本该命中却没命中 |

---

## 开口顺序（可直接说）

1. 这是什么模型、什么精度、上下文多长。
2. 几张什么卡、框架和后端版本是什么。
3. 流量是短还是长、目标是吞吐还是时延。
4. 现在的并行和 PD 切法是什么，基线数字是多少。
5. 然后才进入请求路径和 Profiling。
